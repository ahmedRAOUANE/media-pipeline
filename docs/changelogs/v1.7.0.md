# Changelog

## v1.7.0 (2026-10-29)

### Features

- **Closed-set provider type**: `PipelineProvider` is now `PipelineProviders[keyof PipelineProviders]`. The base package declares only `local: "local"`, so non-augmenting consumers see exactly `"local"` — identical to v1.6.x. Consumers writing their own `Storage` adapter extend the set via TypeScript module augmentation:

  ```ts
  declare module "media-pipeline" {
      interface PipelineProviders {
          r2: "r2";
      }
  }
  ```

  After augmentation, `"r2"` is accepted and `"gcs"` is still rejected — typos remain compile errors.

- **Public type exports**: `PipelineProvider`, `PipelineProviders`, and `PipelineConfig` are now exported from the package root. Previously a consumer writing a custom storage adapter had no public path to either the provider type or the config shape; only the deep path `media-pipeline/dist/types/pipeline` worked, which is not a stable contract.

### Testing

- Added `vitest` (`^5.0.5`); `npm test` runs in CI mode, `npm run test:watch` in watch mode.
- `tests/plugin.test.ts` converted from a `console.log` script into two real assertions (registration + execution).
- New `tests/provider-augmentation.test.ts` proves the positive case: `"r2"` compiles after `declare module "media-pipeline"`, and works end-to-end with a custom `Storage` returning `provider: "r2"`.
- New `tests/provider-bare.test-d.ts` (type-only, never executed) proves the negative case via `@ts-expect-error`: a non-augmenting consumer is rejected when writing `provider: "r2"`.
- `npm run typecheck` now runs **both** programs — base (with augmentation) and `tsconfig.bare.json` (without) — so the closed-type guarantee is enforced on every CI run.
- `vitest.config.mts` (renamed from `.ts`) silences the Vite ESM-in-CJS warning ahead of the `configLoader: 'native'` default.
- `pretest` and `pretypecheck` run `npm run build` first so package self-references (`"media-pipeline"`) resolve against a fresh `dist/`.

### Documentation

- README gains a **Custom Storage Adapters** section documenting the consumer-owned adapter pattern, the augmentation recipe, and the rationale for a closed provider set.
- README's `PipelineResult.provider` type corrected from the literal `"local"` to `PipelineProvider`.
- README's **Current Limitations** rewritten to distinguish built-in vs consumer-owned adapters and to reflect the new script surface.

### Notes

- **Non-breaking.** Existing consumers importing from `"media-pipeline"` and using `localStorage()` see no change: `PipelineProvider` still resolves to `"local"`, and the `provider: "local"` literal inside `localStorage()`'s return value continues to type-check.
- No runtime code changed. The library still ships zero runtime dependencies.

### Migration

None required. Consumers who want to add their own provider name should add a `declare module "media-pipeline"` block — see the README "Registering a provider name" section.
